# AE-044 – Background Job Runner for Ingestion

## Objective

Process accepted ingestion batches asynchronously so upload requests return without waiting for document processing to complete.

## Acceptance Criteria

- [ ] An ingestion job is created in `queued` state for each accepted batch.
- [ ] The upload request returns without waiting for full ingestion processing.
- [ ] An in-process background worker/interval drains queued ingestion jobs.
- [ ] Job state is persisted in MongoDB so queued work is not lost when the application process restarts.
- [ ] The worker claims jobs atomically using a conditional `findOneAndUpdate` so two workers cannot process the same job concurrently.
- [ ] The worker invokes the required PDF/image ingestion pipeline.
- [ ] Jobs remain associated with their corresponding ingestion batch.
- [ ] Each job tracks processing attempts and enforces a maximum retry count.
- [ ] Jobs that exceed the maximum retry count transition to `failed` and are not retried indefinitely.
- [ ] A `startedAt`/heartbeat timestamp is recorded for processing jobs.
- [ ] Stale `processing` jobs can be reclaimed after the configured timeout.
- [ ] Processing is idempotent so retries do not duplicate stored originals or page records.
- [ ] A batch is marked `done` only when all pages are processed successfully.
- [ ] A batch with one or more permanently failed pages is marked `failed`, with successful and failed page counts recorded.
- [ ] Processing failures are recorded on the job with sanitized diagnostic information.
- [ ] A single page-processing operation is bounded by a timeout so a hung page cannot hold the worker indefinitely.
- [ ] Existing authentication and authorization behaviour is preserved where applicable.

## Validation

- [ ] Test that the upload request returns before processing completes.
- [ ] Test that a queued background job is created for an accepted batch.
- [ ] Test successful background processing.
- [ ] Test failed processing and error recording.
- [ ] Test maximum retry behaviour.
- [ ] Test stale `processing` job recovery.
- [ ] Test atomic job claiming under concurrent workers.
- [ ] Test idempotent retry behaviour without duplicate pages or originals.
- [ ] Test complete batch success.
- [ ] Test partial page failure results in `failed` status with correct page counts.
- [ ] Test worker timeout handling.
- [ ] Test that jobs remain associated with the correct batch.
- [ ] Verify ingestion utilities are invoked by the worker.
- [ ] ESLint passes.
- [ ] TypeScript passes.
- [ ] All tests pass.

## Out of Scope

- Designing a distributed production queue beyond what is required by the existing project architecture.
- External queue infrastructure such as Redis/BullMQ.
- Immutable/WORM storage implementation (AE-043).
- Ingestion status API implementation (AE-045).
