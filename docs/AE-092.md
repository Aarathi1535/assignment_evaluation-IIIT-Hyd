# AE-092: Anonymized Script Reference IDs

This document details the objective, design, implementation, and verification of the stable anonymized script reference IDs.

## AE-092 Objective
The goal is to expose a stable, opaque, and human-friendly script reference (e.g. `Script #A7`) to TAs in blind-grading mode. This prevents TAs from seeing raw file paths, scanner diagnostics, student identities, or the raw database ObjectIds.

## Decision to Reuse StudentMapping.anonymousId
To avoid introducing redundant identity schemas, we reuse the existing `StudentMapping.anonymousId` field. This field is:
- Stable and unique within an exam.
- Generated and validated during ingestion/roster mapping.
- Already tracked by the application.

No second anonymous-ID system has been created. The serializing process directly projects this value into the human-friendly display form `Script #${anonymousId}`.

## Fallback Design for Unidentified Scripts
If a script has no identified student (e.g. `student = null`, `needsManualId = true`, or no mapping exists):
- **Requirement**: We must not expose the raw AnswerScript Mongo ObjectId, nor should we use random generation (to ensure stability across repeated requests).
- **HMAC Derivation**: We compute a deterministic 6-character hex suffix from the HMAC-SHA256 of the script's Mongo ID using the server's configured storage secret:
  ```typescript
  const secret = process.env.ORIGINAL_STORAGE_HMAC_SECRET;
  if (!secret || secret.trim() === '') {
      throw new Error('ORIGINAL_STORAGE_HMAC_SECRET is missing or not configured');
  }
  const hmac = crypto.createHmac('sha256', secret).update(scriptId).digest('hex');
  const suffix = hmac.slice(0, 6).toUpperCase();
  scriptReference = `Script #UNASSIGNED-${suffix}`;
  ```
- **Configuration & Fail-Fast Behavior**: If the required environment variable secret is missing or empty, the application throws a configuration error immediately to fail fast, rather than silently falling back to a hardcoded or predictable salt. This guarantees maximum security.

## Cross-Exam Lookup Correctness
The composite key format `${examId}:${studentId}` introduced in AE-090 is fully leveraged. When mapping students, references are resolved using both the student ID and the specific exam ID, guaranteeing that a student with different anonymous IDs in different exams receives the correct context-specific script reference during serialization.

## Bulk Query N+1 Protection
The bulk serialization helper `serializeAnswerScripts` pre-fetches student mapping records in a single query for all exam IDs present in the collection. This prevents N+1 database queries when processing list responses. The fallback hash calculation is performed CPU-side, adding zero database roundtrips for unassigned scripts.
