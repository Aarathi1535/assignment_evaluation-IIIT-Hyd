# AE-047 — Generate Thumbnails per Page

## Objective

Generate a deterministic thumbnail for every successfully extracted page image and persist the thumbnail reference so it can be efficiently consumed by the UI.

Thumbnails are derived assets and are intentionally separate from the immutable original-storage path.

## Scope

- Generate one thumbnail for every successfully extracted page image.
- Store thumbnails using deterministic, mutable storage keys so retries can overwrite/reconcile the same derived asset idempotently.
- Associate each thumbnail with its corresponding `IngestionPage` document.
- Extend `IngestionPage` to store the thumbnail reference and image dimensions.
- Preserve the original page image as the asset of record.
- Thumbnail generation failure must not cause an otherwise successfully processed page to become failed.
- Ensure missing thumbnails can be reconciled on retry.

## Derived Asset Storage Decision

Original uploaded files are protected by the AE-043 immutable/WORM + HMAC storage path.

Page images and thumbnails are derived assets and will **not** use the immutable original-storage path.

Derived assets will use mutable, deterministically-keyed storage so retries can safely overwrite/reconcile the same asset:

`batchId/fileId/pageNumber/thumb.jpg`

This avoids duplicate thumbnail references while preserving immutability/tamper-evidence for the original uploaded files.

The same derived-asset storage decision applies to page images created by AE-046.

## Thumbnail Specification

Each thumbnail must:

- Have a maximum long edge of **200 pixels**.
- Preserve the source aspect ratio.
- Use **JPEG** output.
- Use **JPEG quality 80**.
- Use a **white matte/background** when the source contains transparency.

## Page Model Changes

Update `IngestionPage` to support derived thumbnail metadata:

- Add `thumbnailKey`.
- Add `width`.
- Add `height`.
- Existing Page documents created before these fields exist must report `thumbnailKey` as `null` rather than assuming a thumbnail exists.

The page image dimensions should be persisted so consumers do not need to download the image merely to determine its layout dimensions.

## Acceptance Criteria

- Every successfully extracted page can have a corresponding thumbnail.
- Thumbnail maximum long edge is 200px with aspect ratio preserved.
- Thumbnails are JPEG at quality 80.
- Transparent inputs receive a white matte.
- Thumbnail storage keys are deterministic and mutable.
- Retrying thumbnail generation does not create duplicate thumbnail references.
- `IngestionPage` stores `thumbnailKey`, `width`, and `height`.
- Existing Page documents without thumbnails report `thumbnailKey` as `null`.
- A thumbnail failure does not fail an otherwise successfully processed page.
- When thumbnail generation fails after the page image has been stored, the page remains `PROCESSED` and the missing thumbnail can be reconciled on retry.
- Original uploaded files continue to use the AE-043 immutable/HMAC-protected storage path.
- Relevant tests, TypeScript compilation, and lint pass.
