# AE-096 — Claim/Lock and Release Allocated Script

## Objective
Implement atomic, secure claim (lock) and release operations for allocated answer scripts. This allows teaching assistants (TAs) to safely claim pending scripts for grading (locking them against concurrent claims by other TAs) and release them back to pending if they cannot finish grading, allowing recovery without changing script ownership.

## Implementation

### 1. Database Operations
Modified [`src/services/AllocationService.ts`](file:///c:/Users/AARATHISREE/Desktop/IIIT%20Hyd%20-%20Assignment%20Evaluation/Project%20Repo/assignment-evaluator/src/services/AllocationService.ts):
*   **Atomic Claim (`claimAllocation`)**:
    Transitions an allocation's status from `PENDING` to `IN_PROGRESS` atomically matching the allocation ID, the TA ID, and status `PENDING` using Mongoose `findOneAndUpdate`.
*   **Atomic Release (`releaseAllocation`)**:
    Transitions an allocation's status from `IN_PROGRESS` back to `PENDING` using `findOneAndUpdate`. Supports a `isBackupOperator` flag allowing course Professors/Admins to release allocations belonging to other TAs.
*   **Conflict and Error Handling**:
    *   Returns `404 Not Found` if the allocation does not exist.
    *   Returns `403 Forbidden` if a TA attempts to claim or release an allocation belonging to another TA.
    *   Returns `409 Conflict` if the allocation has already been claimed (status is `IN_PROGRESS`).
    *   Returns `400 Bad Request` if attempting to claim or release `COMPLETED` allocations.

## Concurrency
To guarantee concurrency safety, the database transitions rely exclusively on single-query atomic conditional updates (`findOneAndUpdate` matching the expected status). No vulnerable read-then-write logic is used. A dedicated concurrent-claims unit test verifies that when two identical claim requests arrive simultaneously, exactly one succeeds and the other receives a conflict response.
