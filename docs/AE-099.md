# AE-099 — Mark Allocation Completed Transition

## Objective
Implement a secure, transaction-safe, and atomic state transition from `IN_PROGRESS` to `COMPLETED` for grading allocations (both whole-script and question-wise). This transition is designed to be called by the future Week-7 grading save flow.

## Implementation Details

### 1. Database Operations
Modified [`src/services/AllocationService.ts`](file:///c:/Users/AARATHISREE/Desktop/IIIT%20Hyd%20-%20Assignment%20Evaluation/Project%20Repo/assignment-evaluator/src/services/AllocationService.ts):
* **Atomic Transition (`markCompleted`)**:
  Transitions an allocation's status from `IN_PROGRESS` to `COMPLETED` atomically by matching the allocation ID, status `IN_PROGRESS`, and verifying the actor's authorization.
* **Privilege Levels**:
  * **TA (Primary Owner)**: Can only mark their own allocated scripts as completed.
  * **Professor/Admin (Backup Operators)**: Can mark any allocation as completed on behalf of the assigned TA.
* **Conflict and Error Handling**:
  * Returns `404 Not Found` if the allocation does not exist.
  * Returns `403 Forbidden` if a TA attempts to complete another TA's allocation.
  * Returns `409 Conflict` (idempotency error) if the allocation is already `COMPLETED`.
  * Returns `400 Bad Request` if attempting to complete a `PENDING` allocation.

### 2. Audit Trail Logging
The completion operation runs inside database transactions (via `runInTransaction`) to guarantee that audit logging is transaction-safe and succeeds if and only if the state transition succeeds:
* **Completion Action (`ALLOCATION_COMPLETE`)**:
  Logs successful transition from `IN_PROGRESS` to `COMPLETED`.
  * `user`: The acting user ID.
  * `outcome`: `SUCCESS`
  * `entityId`: The allocation ID.
  * `entityType`: `'Allocation'`
  * `details`: Includes context information:
    * `examId`: The associated exam ID.
    * `answerScriptId`: The answer script ID.
    * `question`: The specific question number (for question-wise allocations) or undefined/null (for whole-script).
    * `taId`: The ID of the TA to whom the script is allocated.
    * `actingUserId`: The ID of the user executing the completion.
    * `isOverride`: `true` if completed by a backup operator (Professor/Admin) who is not the assigned TA, otherwise `false`.

## Concurrency and Idempotency
To ensure complete concurrency safety, the database transitions rely on single-query atomic conditional updates (`findOneAndUpdate` matching the expected status `IN_PROGRESS`). If concurrent requests are sent, at most one will succeed, and subsequent requests will return a `409 Conflict` status since the status is already `COMPLETED`.
