# AE-104a — Relative TA Progress / Bottleneck Detection

## Objective

Provide real-time bottleneck detection and relative progress comparison across Teaching Assistants (TAs) evaluating the same exam. By comparing each TA's individual completion ratio against the cohort median, instructors can identify grading bottlenecks and rebalance workloads before grading milestones are impacted.

---

## 1. Mathematical Definitions & Bottleneck Rules

### 1.1 Completion Ratio
For each teaching assistant assigned to an exam:
$$\text{completionRatio} = \begin{cases} \dfrac{\text{graded}}{\text{total}} & \text{if } \text{total} > 0 \\ 0 & \text{if } \text{total} = 0 \end{cases}$$

* Represented consistently as a floating-point numeric ratio from `0.0` to `1.0` (rounded to 4 decimal places).

### 1.2 Zero-Allocation Exclusion
* Only TAs with $\text{total} > 0$ participate in the cohort median calculation.
* TAs with $\text{total} = 0$ are excluded from the cohort baseline and are marked with `isBottleneck = false`.

### 1.3 Cohort Median Completion Ratio
For an exam with $N$ eligible TAs ($\text{total} > 0$), let $r_0 \le r_1 \le \dots \le r_{N-1}$ be the sorted sequence of completion ratios:
* If $N = 0$: $\text{cohortMedian} = 0.0$
* If $N$ is odd ($N = 2k + 1$): $\text{cohortMedian} = r_k$
* If $N$ is even ($N = 2k$): $\text{cohortMedian} = \dfrac{r_{k-1} + r_k}{2}$

### 1.4 Fixed 20-Percentage-Point Bottleneck Threshold
A TA is flagged as a bottleneck if and only if their completion ratio is **materially lagging** behind the cohort median by **more than 20 percentage points (0.20)**:
$$\text{isBottleneck} = (\text{cohortMedian} - \text{completionRatio}) > 0.20$$

#### Boundary Examples:
| Cohort Median | TA Completion Ratio | Difference | Bottleneck Status | Explanation |
| :--- | :--- | :--- | :--- | :--- |
| **80% (0.80)** | **55% (0.55)** | **25% (0.25)** | **`true`** | Difference (25%) exceeds the 20% threshold ($0.25 > 0.20$). |
| **80% (0.80)** | **60% (0.60)** | **20% (0.20)** | **`false`** | Exactly on the 20% threshold; not strictly greater ($0.20 \ngtr 0.20$). |
| **80% (0.80)** | **65% (0.65)** | **15% (0.15)** | **`false`** | Difference (15%) is within the acceptable 20% margin ($0.15 \le 0.20$). |
| **50% (0.50)** | **50% (0.50)** | **0% (0.00)** | **`false`** | TA is aligned with the cohort median. |

## 2. API Endpoint Specification

### `GET /api/exams/[id]/progress`

* **Authorization**: Requires `Permission.ALLOCATE_SCRIPTS` (Professors, Admins). Unauthorized users (`TA`, `STUDENT`) receive `403 Forbidden`.
* **Exam Scoping**: Aggregations are strictly filtered to the given `examId`.
* **Single Source of Truth**: Reuses the server-side MongoDB aggregation pipeline from AE-098. No duplicate database counts or divergent completion logic are introduced.

## 3. Privacy & Security Guarantees

* **Zero Student PII**: Student IDs, roll numbers, names, email addresses, answer script storage paths, and anonymous mappings are completely excluded from the progress and bottleneck payloads.
* **Professor-Facing TA Visibility**: TA identities (`taId`, `name`) are intentionally visible to authorized instructors to coordinate evaluation assignments.
* **Strict Role-Based Access Control**: Only roles possessing `Permission.ALLOCATE_SCRIPTS` can access progress and bottleneck analytics.
