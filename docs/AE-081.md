## End-to-End Flow

1. Upload assignment PDFs/images.
2. Process pages and create derived assets.
3. Detect cover sheets and identify students using QR/OMR.
4. Assemble pages into logical answer scripts.
5. Review and correct script identification when required.
6. Approve the ingestion assembly.
7. Seal the approved assembly to detect later drift.
8. Allow grading allocation only after ingestion approval.

## Defects and Fixes — AE-080

- Equal-precedence identification can overwrite when the detected student changes.
- Operator identification remains protected from automatic overwrite.
- Obsolete scripts are soft-deactivated instead of hard-deleted.
- Referenced grading/allocation data is preserved.
- Reassembly is blocked after ingestion approval.

## Key Decisions

- Original uploads are immutable source assets.
- Derived assets are mutable and can be regenerated.
- Operator identification takes precedence over automated identification.
- Approval applies to the logical script assembly.
- The HMAC seal covers the assembly state rather than original file bytes.
- The seal is deterministic and can detect later assembly drift.
- Corrections are blocked after approval until revocation.
- Allocation is blocked until ingestion is approved.
- Dashboard counts are calculated server-side with MongoDB as the source of truth.
