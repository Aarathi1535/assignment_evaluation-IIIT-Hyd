# AE-042 – Batch Upload Pipeline

## Objective

Accept multipart PDF/image scanner uploads and create an ingestion batch for processing.

## Acceptance Criteria

- [ ] `POST /api/ingest` accepts multipart PDF/image uploads.
- [ ] Maximum single-file size is 50 MB.
- [ ] Maximum files per batch is 20.
- [ ] Maximum total request size is 200 MB.
- [ ] Maximum PDF page count is 200 pages.
- [ ] Requests exceeding any configured limit are rejected with HTTP 413.
- [ ] Uploaded file types are verified using magic bytes rather than trusting `Content-Type` or file extensions.
- [ ] Encrypted/password-protected PDFs are explicitly rejected.
- [ ] A unique `batch_id` is generated server-side for each accepted upload.
- [ ] An ingestion job/status record is created in `queued` state and associated with the batch.
- [ ] The batch ownership field (`uploadedBy`) is set server-side from the authenticated session and is never accepted from the request body.
- [ ] Batch access is owner-scoped in the repository layer.
- [ ] Batch creation requires the appropriate ingestion permission and only authorized roles can create batches.
- [ ] The original client filename is stored only as display metadata; it is never used as a storage path or identifier.
- [ ] Storage identifiers are generated server-side.
- [ ] Invalid or unsupported uploads are rejected appropriately.
- [ ] Batch creation produces an audit entry with the appropriate `SUCCESS` or `FAILURE` outcome.
- [ ] Uploaded PDFs/images are treated as untrusted input and processing is bounded by the configured limits.

## Validation

- [ ] API test for a valid PDF upload.
- [ ] API test for a valid image upload.
- [ ] Test multi-page PDF input.
- [ ] Test file-size limit.
- [ ] Test files-per-batch limit.
- [ ] Test total-request-size limit.
- [ ] Test PDF page-count limit.
- [ ] Test magic-byte validation with a forged `Content-Type`/extension.
- [ ] Test encrypted/password-protected PDF rejection.
- [ ] Test server-generated batch ownership.
- [ ] Test unauthorized/unauthenticated batch creation.
- [ ] Test owner-scoped batch access.
- [ ] Test malicious filenames such as `../../etc/passwd` and null-byte filenames.
- [ ] Test `queued` ingestion job creation.
- [ ] Test audit logging for both success and failure outcomes.
- [ ] Verify response contains `batch_id` and queued job information.
- [ ] ESLint passes.
- [ ] TypeScript passes.
- [ ] All tests pass.

## Out of Scope

- Background job execution/worker implementation (AE-044).
- Immutable/WORM storage implementation (AE-043).
- Ingestion status API beyond creating the initial `queued` status record (AE-045).
- Advanced PDF security analysis beyond bounded, validated input handling.
