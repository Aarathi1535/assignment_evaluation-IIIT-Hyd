# AE-094 — TA Assigned Scripts Work-Queue API

## Objective
The TA Work-Queue API retrieves grading allocations assigned to the currently authenticated Teaching Assistant. It integrates with the permission and anonymizer subsystems to ensure strict student privacy (blind grading) on a per-exam basis while serving as the backend source for the grading work queue.

## Implementation
*   **API Route**: Exposes `GET /api/allocations`.
*   **TA Identification & Restriction**: Resolves the caller using `requirePermission(Permission.VIEW_ASSIGNED_SCRIPTS)`. The MongoDB query is strictly restricted to query allocations matching `ta: auth.user.id`, ensuring TAs can never retrieve allocations belonging to others.
*   **Optional `examId` Filter**: Parses the optional `examId` query string parameter. If provided, it validates the ObjectId format. If the TA has no matching allocations for a valid `examId`, it returns an empty result set with HTTP 200 OK.
*   **Pagination Support**: Supports optional `page` and `limit` query parameters for paginated retrieval. Validates that both are positive integers (returns HTTP 400 Bad Request if invalid).
*   **Deterministic Ordering**: Applies a deterministic sort order of `_id` ascending before pagination offset/limit calculations.
*   **Question-wise Context**: Incorporates question-wise metadata (`question` number) in the allocation return object, along with the current grading `status` (`PENDING`, `IN_PROGRESS`, `COMPLETED`).
*   **Permissions Enforced**: Enforces authentication and the existing `Permission.VIEW_ASSIGNED_SCRIPTS` permission at the route level.

## Anonymization and Privacy
*   **Anonymizer Integration**: Dynamically extracts nested `answerScript` objects from allocations and runs them through `Anonymizer.serializeAnswerScripts(scripts, viewer)`.
*   **Viewer Context**: Passes the authenticated caller's identity and role context (e.g. `{ id: auth.user.id, role: auth.user.role }`) to the anonymizer.
*   **N+1 Exam Lookup Avoidance**: The bulk serializer resolves the blind grading configuration by querying distinct exams in a single batch (using `Exam.find({ _id: { $in: examIds } })`), avoiding N+1 individual queries (e.g. `Exam.findById`) for each script.
*   **Blind Mode Restrictions**: Under blind-grading active exams, student identification details (specifically `student`, `qrStudentId`, `omrStudentId`, and `candidateStudentId`) are entirely omitted from the response.

## API Behaviour

### Request
*   **Method**: `GET`
*   **Path**: `/api/allocations`
*   **Query Parameters**:
    *   `examId` (optional, string): Valid MongoDB ObjectId string representing the exam to filter allocations by.
    *   `page` (optional, integer): The page number to retrieve. Must be a positive integer >= 1. Default is `1`.
    *   `limit` (optional, integer): The number of results per page. Must be a positive integer >= 1. Default is `20`. Maximum limit is clamped to `100`.

```json
  "data": {
    "allocations": [
      {
        "_id": "60c72b2f9b1d8a001f8e1234",

        "status": "PENDING",
        "question": 2,
        "answerScript": {
          "_id": "60c72b2f9b1d8a001f8e1236",
          "exam": "60c72b2f9b1d8a001f8e1235",
          "anonymousId": "ANON-POTTER-777",
          "scriptReference": "Script #ANON-POTTER-777",
          "startPageNumber": 1,
          "endPageNumber": 4,
          "pageCount": 4,
          "isActive": true,
          "createdAt": "2026-08-27T08:00:00.000Z",
          "updatedAt": "2026-08-27T08:00:00.000Z"
        }
      }

    "pagination": {
      "page": 1,

      "total": 1,
      "totalPages": 1,
      "hasNextPage": false,
      "hasPreviousPage": false
    }
  }

```

#### Error Responses
*   **400 Bad Request**: Raised when `examId` is specified but has an invalid MongoDB ObjectId format, or if `page` or `limit` parameters are not positive integers.
    ```json
    {
      "success": false,
      "message": "Invalid page parameter. It must be a positive integer.",
      "data": null
    }
    ```
*   **401 Unauthorized**: Raised when no session cookie is supplied.
*   **403 Forbidden**: Raised when the authenticated user does not possess `Permission.VIEW_ASSIGNED_SCRIPTS` (e.g. students or professors).
