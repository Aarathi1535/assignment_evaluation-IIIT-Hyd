# AE-048 — Handle Mixed Inputs (Image-Only, Multi-File)

## Objective

Extend the ingestion pipeline to robustly handle batches containing image inputs, multiple PDFs, and mixed PDF/image files.

## Scope

- Accept image-only batches.
- Accept multiple PDF files in a single batch.
- Accept mixed PDF and image files in the same batch.
- Produce the same normalized per-page assets and Page documents regardless of input type.
- Preserve deterministic batch-level file/page ordering and associations.
- Use the canonical normalized page-image representation defined by AE-046 for all supported input types.
- Preserve the existing reject-whole-batch behaviour when any uploaded file fails validation.

## Ordering Decision

File ordering is based on **receipt order**.

- The upload flow assigns an explicit zero-based `fileIndex` to each file when the batch is received.
- `fileIndex` is persisted so reprocessing the same batch preserves the original ordering.
- Within each file, pages are numbered starting at `1`.
- The canonical cross-file ordering key is `(fileIndex, pageNumber)`.
- A standalone image always has `pageNumber = 1` within its source file.
- Reprocessing the same batch must produce identical `(fileIndex, pageNumber)` ordering.

Client multipart order is therefore captured as explicit persisted metadata rather than being relied upon implicitly during later processing.

## Partial File Failure Decision

AE-048 retains the existing **reject-whole-batch** behaviour.

If any uploaded file fails the existing validation requirements, the entire batch is rejected before ingestion begins. Other files in the same request are not partially ingested.

This avoids introducing a separate `failedFiles` model/counter and avoids defining new semantics for whether a partially ingested batch is `done` or `failed`.

Per-page failures during processing remain governed by the existing ingestion job semantics (`processedPages` / `failedPages`).
