# AE-076 — Review Dashboard: Counts, Unmatched, Blanks

This document describes the design, implementation, count aggregation semantics, and tests of the **Ingestion Review Dashboard** introduced in AE-076.

---

## 1. Architectural Design & Aggregation Logic

The Review Dashboard runs on the server-side using Mongoose MongoDB aggregation pipelines. Aggregation runs directly on Mongoose model collections (`AnswerScript` joined with `IngestionPage`) in a single pass to fetch counts needed by the tiles.

### Aggregate counts categories
The server aggregates:
- **Total Scripts**: Count of all active scripts associated with the exam.
- **Unmatched (Manual Identification)**: Scripts where the student is null (`student === null`) or manually flagged for review (`needsManualId === true`).
- **Blank Scripts**: Scripts where every single page belonging to that script is marked `nearBlank === true`.
- **Duplicates**: Scripts marked with `manualIdReason === 'DUPLICATE_STUDENT'` or where at least one of their pages has `isDuplicate === true`.
- **ID Conflicts**: Scripts with identification conflicts (`hasIdentificationConflict === true`).

### Performance Optimization ($facet)
All categories are aggregated concurrently using a single MongoDB `$facet` stage. This avoids making five separate database calls and avoids loading all documents into application memory.

## 2. Count Semantics & Definitions

### Exact Blank-Script Semantics
- A script is **blank** if and only if **all** of its associated pages have `nearBlank === true` and the page count is greater than zero.
- A script with a mix of blank pages and non-blank pages is **not blank**.
- An empty script (0 pages) is **not blank**.

```
[Script 1] ── Pg 1 (nearBlank: true) ── Pg 2 (nearBlank: true)  ==> BLANK (100% blank pages)
[Script 2] ── Pg 1 (nearBlank: true) ── Pg 2 (nearBlank: false) ==> NOT BLANK (Mixed)
```

### Unmatched / Manual-ID Semantics
A script is unmatched if:
- `needsManualId === true` (OCR/OMR/QR failed or found multiple possibilities)
- OR `student === null` (unidentified student)

## 3. Owner Scoping & Authorization

- All Review Dashboard operations (both the counts aggregation and listing matching scripts) are owner-scoped.
- The service calls `ExamRepository.getExamById` using the reviewer's context (`actingUserId` and `actingUserRole`).
- If the reviewer is a Professor, they can only access exams they created. If they are a TA, they can only access exams for courses they assist.
- Unauthorized requests safely fail with a standard `404 Not Found` or `403 Forbidden` response and do not expose another user's exam data.

## 4. API Endpoints

- **`GET` `/api/exams/[id]/ingestion-summary`**
  - Returns counts summary:
    ```json
    {
      "success": true,
      "message": "...",
      "data": {
        "counts": {
          "totalScripts": 120,
          "unmatched": 4,
          "blank": 1,
          "duplicate": 0,
          "conflict": 0
        }
      }
    }
    ```
  - If optional query parameter `category` is supplied (e.g. `?category=unmatched`), returns the counts and the matching scripts list:
    ```json
    {
      "success": true,
      "message": "...",
      "data": {
        "counts": { ... },
        "scripts": [
          {
            "_id": "...",
            "batchId": "...",
            "startPageNumber": 1,
            "endPageNumber": 2,
            "pageCount": 2,
            "pages": [ ... ],
            "omrResolvedStudent": null,
            "qrResolvedStudent": null
          }
        ]
      }
    }
    ```

## 5. UI Views & Interactive Drill-down

- **Summary Cards**: Displays five tiles mapping to the aggregated categories. Selecting a card filters the active drill-down view.
- **Drill-down Scripts**: Lists matching scripts with their page thumbnails. 
- **Inline Student Bind**: Unidentified scripts contain an inline **Identify** dropdown. Reviewers can type to search the exam student roster and bind students directly from the dashboard.
- **Edit Script Composition**: Contains direct link buttons to the interactive editor page (`batches/[id]/preview?scriptId=[scriptId]`) for that script's batch to perform split/merge/reorder operations.

## 6. Verification & Test Suite

The test suite in `src/__tests__/ReviewDashboard.test.ts` contains 10 comprehensive tests verifying:
1. Correct total script count.
2. Correct unmatched script counts.
3. Blank script semantics (all pages blank).
4. Mixed blank page semantics (not blank).
5. Duplicate counts.
6. Conflict counts.
7. Access controls (owner scoping).
8. Empty exams.
9. Verification that aggregation queries MongoDB.
10. Category script filtering.
