# AE-109 — Professor Dashboard: Production Hardening

### Objective

Harden the completed dashboard for normal production usage.

---

### What we're building

Dashboard polish and resilience.

---

### Done when

- Loading state is displayed while dashboard data is being fetched.

- Empty state is displayed when no grading data exists.

- Error state is displayed when dashboard data cannot be loaded.

- Dashboard remains usable after API failures.

- A `live_updates_unavailable` state is displayed when the SSE live-update channel is unavailable.

- Dashboard remains usable with the latest available data when live updates are unavailable.

- Layout works correctly on tablet-sized screens.

- Layout works correctly on desktop screens.

- Existing authorization behavior is preserved.

---

### Where to look

- `src/app/(dashboard)/professor/page.tsx`
- Existing dashboard API route handlers
- `src/services/ProgressEventService.ts`
- `requirePermission`
- `(dashboard)` layout

---

### Validation

- [ ] `npx vitest run`
- [ ] `npx tsc --noEmit`
- [ ] `npm run lint`
- [ ] `git diff --check`

Loading, empty, error, live-update degradation, tablet, and desktop behavior should be verified manually because the current Vitest environment does not provide a DOM rendering environment.

---

### Anti-invention clause

> **Strict Semantic Boundary:** Do not infer dashboard state, grading progress, completion time, ETA, or grading duration from fields whose semantics do not guarantee those values.
