# AE-064 — Backend Endpoints for Remap / Merge / Split

## Objective

Provide authenticated backend operations for persisting manual corrections to
script/page relationships after ingestion.

## Scope

Provide backend operations for:

- Moving/remapping a page between scripts.
- Merging scripts.
- Splitting a script into corrected script groups.
- Reordering pages within a script.

All correction operations must keep `IngestionPage.answerScript` and the
corresponding `AnswerScript` range/count fields consistent.

## Source of Truth

`IngestionPage.answerScript` remains authoritative for page-to-script
membership.

`AnswerScript.startPageNumber`, `endPageNumber`, and `pageCount` are derived /
denormalized summaries and must always match the actual linked pages.

## Atomicity

Each correction is a multi-document write and must be atomic.

- Use MongoDB sessions/transactions.
- If any part of an operation fails, the entire operation must roll back.
- No partially updated page/script relationships may remain.
- Add tests verifying range/count consistency after every operation type.
- Rollback behavior must be tested for a failed correction.

## Correction Rules

### Merge

- If both scripts are identified with different students, reject the merge.
- Do not silently overwrite or transfer student identity.
- Return a clear validation error for identity conflicts.

### Split

- Newly created script ranges must not violate the existing unique
  `(batchId, fileIndex, startPageNumber)` constraint.
- Recompute script range/count fields from the resulting page relationships.

### Empty Scripts

- Moving the last page out of a script removes the now-empty script.
- No empty `AnswerScript` should remain after a successful correction.

### Reordering

- Persist the corrected page ordering.
- Keep page ordering deterministic after the operation.
- Recompute affected script range/count information where required.

## Concurrency

Support optimistic locking for concurrent corrections to the same
batch/script.

- Use a version/revision field or equivalent concurrency check.
- Reject stale updates when another reviewer has already modified the
  affected data.
- Do not silently overwrite another reviewer's correction.

## Authorization

- Require `EDIT_EXAM`.
- Verify batch/exam ownership.
- Reject unauthorized access.
- Preserve the existing 404-not-403 behavior where applicable.

## Audit

Every successful correction must be audit-logged with:

- acting user
- affected batch/script/page
- operation performed
- previous state
- resulting state
- timestamp

## Acceptance Criteria

- Remap operation persists atomically.
- Merge operation persists atomically.
- Split operation persists atomically.
- Reorder operation persists correctly.
- Failed operations roll back completely.
- `IngestionPage.answerScript` remains authoritative.
- Script ranges/counts match actual linked pages after every operation type.
- Identified-script conflicts during merge are rejected safely.
- Split operations do not violate script uniqueness constraints.
- No empty scripts remain after moving their last page.
- Concurrent stale updates are rejected.
- All correction operations are authorization-checked.
- All successful corrections are audit-logged.
- Invalid operations do not leave partial state.
- Relevant tests, TypeScript, ESLint, and diff checks pass.

## Out of Scope

- Correction UI — **AE-063**.
- Manual student-ID assignment UI — **AE-062**.
- New splitting algorithms.
- OCR/QR changes.
- Student identification logic.
