# AE-038 – Rubric Model & Backend APIs

## Objective

Implement backend support for configurable grading rubrics that can be created and managed by authorized staff for each exam.

The feature enables professors to define question-wise marking schemes, grading criteria, and maximum marks while enforcing ownership and role-based authorization.

---

## Functional Requirements

### Rubric Model

- Each rubric is associated with exactly one exam.
- A rubric contains one or more questions.
- Each question contains:
  - Question number
  - Maximum marks
  - One or more grading criteria (sub-parts)
- Each criterion contains:
  - Description
  - Points
- Rubrics store the creator and version metadata.

---

### Authorization

Only the following roles may create or modify rubrics:

- ADMIN
- PROFESSOR

Authorization follows the existing owner-scoped exam access model.

Unauthorized users must receive appropriate HTTP responses.

---

### API Endpoints

Implemented endpoints:

- POST /api/rubrics
- GET /api/rubrics/[id]
- PUT /api/rubrics/[id]

---

### Validation

Server-side validation includes:

- Required fields
- Positive marks and points
- Duplicate question detection
- Criterion points must not exceed question maximum marks
- Unknown field rejection

---

## Acceptance Criteria

- Authorized professors can create rubrics.
- Unauthorized users cannot create or modify rubrics.
- Owner-scoped authorization is enforced.
- Validation errors return appropriate responses.
- Rubrics can be retrieved and updated by authorized users.
- Existing exam authorization behaviour remains unchanged.

---

## Validation Performed

---

## Security Notes

- Reuses the existing owner-scoped ExamRepository instead of duplicating authorization logic.
- Follows deny-by-default authorization.
- Audits successful and failed rubric operations.
