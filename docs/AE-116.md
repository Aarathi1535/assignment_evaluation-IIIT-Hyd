# AE-116 — Activity Feed on Professor Dashboard

## Objective

Allow authorized users (Professors and Admins) to view recent grading and allocation actions on the Professor Dashboard from existing `AuditLog` records without creating duplicate history models or collections.

## Architecture & Single Source of Truth

1. **Existing AuditLog Infrastructure (`src/models/AuditLog.ts`)**:
   - `AuditLog` is the single source of truth for all operational audit records.
   - Captures actions, actor `user`, `entityId`, `entityType`, `outcome`, `details`, and `createdAt` timestamps.
2. **Reuse of Audit Actions**:
   - Reuses events written by AE-113/AE-110 (`ALLOCATION_REASSIGN`), TA actions (`ALLOCATION_CLAIM`, `ALLOCATION_RELEASE`, `ALLOCATION_COMPLETE`), script operations (`ANSWERSCRIPT_IDENTIFIED`, `SCRIPT_REMAP`, `SCRIPT_MERGE`), and exam ingestion/configuration events (`INGESTION_APPROVED`, `INGESTION_APPROVAL_REVOKED`, `EXAM_BLIND_GRADING_TOGGLED`, `GRADE_PUBLISHED`).
3. **No Duplicate Persistence Model**:
   - No separate `Activity` collection, model, or cache is introduced.
   - Directly queries the existing `AuditLog` collection.

## Service Layer (`AllocationService.getActivityFeed`)

- **Method**: `AllocationService.getActivityFeed(viewer?, options?)`
- **Filtering**:
  - Targets relevant grading/allocation action types (`GRADING_ACTIVITY_ACTIONS`).
  - Filters out failed attempts (`outcome: { $ne: 'FAILURE' }`).
  - Optional `examId` filtering (`details.examId` or `entityId`).
- **Ordering & Limits**:
  - Deterministic newest-first order (`.sort({ createdAt: -1, _id: -1 })`).
  - Database-level limiting (`.limit(limit)`) with default `limit = 10` and upper cap of 100.
- **Batch Resolution for Current Result Set Only**:
  - Resolves referenced users (`log.user`, `previousTaId`, `newTaId`, `taId`).
  - Resolves referenced exams and their course codes.
  - Resolves referenced answer scripts with anonymization via `Anonymizer`.
  - Builds human-readable activity descriptions.

## API Endpoint

- **Route**: `GET /api/professor/activity`
- **File**: `src/app/api/professor/activity/route.ts`
- **Authorization**:
  - Enforces `Permission.ALLOCATE_SCRIPTS` via `requirePermission(Permission.ALLOCATE_SCRIPTS)`.
  - Accessible to **Professors** and **Admins**.
  - Unauthenticated requests return `401 Unauthorized`.
  - Unauthorized roles (TAs, Students) return `403 Forbidden`.
- **Query Parameters**:
  - `limit`: optional positive integer (1 to 100, default 10).
  - `examId`: optional valid MongoDB ObjectId string.

## UI Components (`ProfessorActivityFeed`)

- **Component**: `src/components/ProfessorActivityFeed.tsx`
- **Embedded in**: `src/app/(dashboard)/professor/page.tsx`
- **Features & UI States**:
  - **Loading State**: Clean spinner and message during data fetch.
  - **Empty State**: Friendly `EmptyState` when no activities exist.
  - **Error State**: Non-blocking alert with retry mechanism; errors in activity feed do not break other dashboard cards (courses/exams).
  - **Action Badges**: Distinct color-coded badge per activity type (e.g. Reassigned, Claimed, Completed, Approved, Blind Grading).
  - **Contextual Chips**: Course code, question pill (e.g. `Q2`), script anonymous ID badge, acting user name, and relative timestamp.
  - **Manual Refresh**: Dedicated refresh button in header.

## Acceptance Criteria Mapping

- [x] **AC 1**: Existing `AuditLog` collection reused without creating new models or tables.
- [x] **AC 2**: Successful `ALLOCATION_REASSIGN` events and grading actions appear in the feed.
- [x] **AC 3**: Returns activities in deterministic newest-first order.
- [x] **AC 4**: Uses database-level limiting (`.limit(limit)`).
- [x] **AC 5**: Resolves exam, script, question, and user context.
- [x] **AC 6**: Protected by `Permission.ALLOCATE_SCRIPTS` (Professors and Admins).
- [x] **AC 7**: Unauthorized users receive 403 Forbidden.
- [x] **AC 8**: Unauthenticated requests receive 401 Unauthorized.
- [x] **AC 9**: Non-blocking error handling in UI.
- [x] **AC 10**: Zero sensitive credentials/tokens leaked.
