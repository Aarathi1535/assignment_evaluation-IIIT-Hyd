# AE-057 — Batch to N Scripts Integration Test

## Objective

Add an end-to-end integration test proving that an ingestion batch is correctly split into the expected number of AnswerScript records and that every IngestionPage is linked to the correct script.

**Architecture update:** This ticket follows the revised architecture established by **#39, #40, #41, and #42**. AnswerScript is the script-level identity unit, splitting determines page membership independently of student identity, and IngestionPage.answerScript persists page-to-script membership.

## Scope

- Test the real StudentRosterMappingService.assembleAndMapAnswerScripts flow.
- Verify cover-page splitting produces the expected scripts.
- Verify fixed-page splitting produces the expected scripts.
- Verify persisted AnswerScript records.
- Verify IngestionPage.answerScript relationships.
- Verify canonical script and page ordering.
- Verify pages are not cross-linked between scripts.
- Verify reprocessing is idempotent.
- Verify changed splitting boundaries correctly update page-to-script relationships.

## Acceptance Criteria

- A realistic batch produces the expected number of AnswerScript records.
- Cover-page splitting is verified end-to-end.
- Fixed-page splitting is verified end-to-end.
- Every page is linked to the correct persisted AnswerScript.
- Script boundaries and page ordering are correct.
- Reprocessing the same batch does not create duplicate AnswerScript records.
- Changed splitting boundaries replace stale page-to-script relationships correctly.
- Incomplete fixed-page groups are surfaced for manual review.
- Existing splitting and roster-mapping tests continue to pass.

## Out of Scope

- New splitting strategies.
- Changes to production splitting logic.
- Changes to student identification or roll-number handling.
- Grading behavior.
- Operator identification.
- OCR identification.

## Dependencies

**Depends on:**

- **#43 / AE-054** — Cover-boundary splitting strategy.
- **#44 / AE-055** — Fixed-page splitting strategy.
- **#45 / AE-056** — Page-to-AnswerScript persistence.

**Result:**

Provides end-to-end integration coverage for the complete batch → splitting → AnswerScript → page-linking flow.
