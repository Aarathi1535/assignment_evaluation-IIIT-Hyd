# AE-052: Generate Printable QR Cover Sheets

## 1. Overview & Purpose
AE-052 provides an automated, printable cover-sheet generator for examinations. Professors and administrators can generate a multi-page PDF where each page corresponds to exactly one enrolled student's cover sheet. Each cover sheet contains examination details, candidate identification, student instructions, and a high-contrast QR code encoding the exact deterministic payload required for automated scanning in AE-050 and student roster resolution in AE-051.

---

## 2. API Endpoint Specification

### `POST /api/exams/[id]/cover-sheets`

Generates and streams an A4 PDF document containing formatted cover sheets for the target examination.

#### Request Headers
- `Authorization` / Session Cookie: Authenticated session for `PROFESSOR` or `ADMIN`
- `Content-Type`: `application/json` (optional if requesting all enrolled students)

#### Request URL Parameters
- `id`: MongoDB ObjectId string representing the target `Exam._id`

#### Request Body (Optional)
```json
{
  "studentIds": [
    "660000000000000000000002",
    "660000000000000000000003"
  ]
}
```
- If `studentIds` is omitted or empty body: generates cover sheets for **all** enrolled students in the exam's roster.
- If `studentIds` is provided: generates cover sheets **only** for the specified enrolled students.

#### Success Response
- **Status**: `200 OK`
- **Headers**:
  - `Content-Type: application/pdf`
  - `Content-Disposition: attachment; filename="coversheets-[examId].pdf"`
  - `Content-Length: <size_in_bytes>`
- **Body**: Binary PDF stream

#### Error Responses
- `400 Bad Request`:
  - Invalid Exam ID format (non-ObjectId)
  - `studentIds` array contains invalid ObjectId strings
  - One or more requested `studentIds` are not enrolled in the exam's roster
  - No enrolled students found for the exam
  - Requested student count exceeds `MAX_COVER_SHEETS_PER_REQUEST`
- `401 Unauthorized`: Session unauthenticated
- `403 Forbidden`: User role is not `PROFESSOR` or `ADMIN` (via `Permission.EDIT_EXAM`)
- `404 Not Found`: Exam does not exist or access is denied to non-owning professor (deny-by-default)

---

## 3. Authorization & Owner Scoping

AE-052 integrates directly with the existing `ExamRepository.getExamById(examId, actingUserId, actingUserRole)` pattern:
- **`ADMIN`**: Global access to generate cover sheets for any active examination.
- **`PROFESSOR`**: Scoped strictly to exams where `exam.createdBy === actingUserId`.
- **Deny-By-Default**: Non-owning professors receive `404 Not Found` (rather than `403 Forbidden`) to prevent resource enumeration.
- **`STUDENT` / `TA`**: Denied by route permission guard (`Permission.EDIT_EXAM`).

---

## 4. Roster Validation & Request Limits

1. **Roster Aggregation**:
   The set of eligible students is derived from:
   - `Exam.enrolledStudents` (`ObjectId[]`)
   - `StudentMapping.find({ exam: exam._id })` (`mapping.student`)
   - `Course.enrolledStudents` (associated course roster)
2. **Selective Request Validation**:
   If specific `studentIds` are requested, every ID must be present in the aggregated roster. If any ID is missing or not enrolled, the request fails with `400 Bad Request`.
3. **Generation Limit**:
   - Environment variable: `MAX_COVER_SHEETS_PER_REQUEST` (Default: `100`).
   - If target student count exceeds this limit, the request fails with `400 Bad Request` to protect server memory and CPU resources.

---

## 5. PDF & Page Formatting Contract

- **Page Size**: Standard ISO **A4** (`PageSizes.A4` = `[595.28 pt, 841.89 pt]`).
- **Page Count**: Exactly **1 page per student** (`totalPages === targetStudents.length`).
- **Page Layout**:
  - **Header Banner**: "EXAMINATION COVER SHEET", system branding, institutional title.
  - **Exam Metadata**: Exam Title, Course Code & Name, Exam Date, Total Marks.
  - **Candidate Identification**: Student Name, Student MongoDB `_id` (`student._id.toString()`), Student Email.
  - **QR Code Center**: 220x220 pt QR code with high-contrast quiet zone and white backing box.
  - **Submission Instructions**: Explicit warnings regarding cover sheet preservation as Page 1, avoiding folding/stapling through the QR code, and sequential answer page numbering.

---

## 6. QR Code Payload Specification

### Exact Payload Contract
```
<examId>:<studentId>
```
Where:
- `examId` = `exam._id.toString()` (24-character hexadecimal MongoDB ObjectId)
- `studentId` = `user._id.toString()` (24-character hexadecimal MongoDB ObjectId of the student `User` document)
- Separator: `:` (single colon)

*Example*:
`660000000000000000000020:660000000000000000000002`

### Intentional Unsigned Payload Decision
AE-052 intentionally produces an **unsigned, unencrypted payload** (`examId:studentId`):
1. **Decoder Transparency**: Allows standard barcode/QR scanners and downstream services (`CoverSheetDetector`) to inspect candidate metadata without distributing symmetric encryption keys or HMAC secrets to scanning nodes.
2. **Ingestion Verification**: Tampering is mitigated downstream by AE-051 roster reconciliation (`StudentRosterMappingService`), which validates that the decoded `studentId` is actively enrolled in the batch's associated `examId` and enforces deterministic duplicate conflict rules in the database.
3. **No Cryptographic Bloat**: Keeps the QR matrix compact (Version 2-3 QR code) for maximum scan reliability on low-resolution mobile or scanner feeds.

## 7. AE-052 $\rightarrow$ AE-050 $\rightarrow$ AE-051 Compatibility

1. **CoverSheetDetector (AE-050)**:
   - Decodes the QR code on Page 1.
   - When the payload is in the format `examId:studentId`, `CoverSheetDetector` retains `candidateStudentId = "examId:studentId"` and populates `metadata.examId` and `metadata.studentId`.
   - Backward compatibility: Non-colon payloads (e.g. `STU-MANUAL-001`) remain intact without errors.
2. **StudentRosterMappingService (AE-051)**:
   - When receiving `candidateStudentId` in `examId:studentId` format, parses the student `ObjectId` string (`parts[1]`).
   - Resolves the candidate against `userByIdMap` (`User._id`) and verifies enrollment against the exam roster.
