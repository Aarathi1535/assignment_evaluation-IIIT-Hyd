# AE-091: Per-Exam Blind-Grading Toggle

This document details the objective, design, and verification of the per-exam blind-grading toggle feature.

## Purpose of the Per-Exam Blind-Grading Toggle
The toggle allows course staff (professors/admins) to enable or disable blind-grading mode for individual exams. Future TA-facing routing and grading workflows will read this setting to determine whether to strip student PII and serve anonymous IDs instead.

## Server-Side Authorization
Access control is enforced purely server-side based on the user's authenticated session.
- **Required Permission**: `Permission.ALLOCATE_SCRIPTS`
- **Methodology**: Uses the centralized project authorization helper `requirePermission(Permission.ALLOCATE_SCRIPTS)`.
- **Client Security**: The endpoint does not trust any user role, permission, or authorization flags supplied via the request body or query parameters.

## The Freeze Rule (Grading Commenced Guard)
To prevent downstream data mismatch or accidental deanonymization mid-grading, the blind-grading setting is frozen once grading has commenced.
- **Grading Commenced Definition**:
  1. A `Grade` document exists for any answer script belonging to this exam, OR
  2. Any TA script allocation for this exam has a status other than `PENDING` (e.g. `IN_PROGRESS` or `COMPLETED`).
- **Enforcement**: Reuses the static validator method `AllocationService.checkGradingCommenced` to enforce this check in a single reusable way. If grading has commenced, the update is rejected with a `400 Bad Request` HTTP error, no database changes occur, and no audit entries are generated.

## Audit Logging
Successful changes to the blind-grading setting must be logged to the `AuditLog` collection:
- **Action**: `EXAM_BLIND_GRADING_TOGGLED`
- **Outcome**: `SUCCESS`
- **Details Logged**:
  - `examId`: The ID of the modified exam.
  - `previousValue`: The previous boolean value of `blindGrading`.
  - `newValue`: The new boolean value of `blindGrading`.
- **Actor Identification**: The log records the authenticated user ID executing the change.
- Failed or rejected toggle requests (e.g., unauthorized access or post-commencement attempts) are not written to the audit log.

## No-Op Behavior
If the requested value matches the current value of the `blindGrading` property:
- The setting is not rewritten.
- The request returns `200 OK` with a payload indicating `changed: false`.
- No audit log entry is written.

## Route Endpoint Details
- **Route**: `POST /api/exams/[id]/blind-grading`
- **Input JSON Payload**:
  ```json
  {
    "blindGrading": true
  }
  ```
