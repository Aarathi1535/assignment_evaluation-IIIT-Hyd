# AE-045 – Ingestion Status Model + API

## Objective

Track ingestion progress and expose the current processing status and page counts for an ingestion batch.

## Acceptance Criteria

- [ ] An ingestion status model is persisted.
- [ ] Supported states are `queued`, `processing`, `done`, and `failed`.
- [ ] Valid state transitions are enforced as `queued → processing → done|failed`; invalid or backward transitions are rejected.
- [ ] The model stores `createdAt`, `updatedAt`, `startedAt`, and `completedAt` timestamps.
- [ ] The model tracks `totalPages`, `processedPages`, and `failedPages`.
- [ ] `GET /api/ingest/{id}` returns the current status and relevant page counts.
- [ ] Failed batches store a sanitized failure reason suitable for diagnosis without exposing raw parser stack traces.
- [ ] Failure details are only exposed to authorized users.
- [ ] Batch ownership is enforced in the repository layer.
- [ ] Access is deny-by-default; unknown roles return no batch.
- [ ] A non-owner receives `404`, not `403`, so batch existence is not disclosed.
- [ ] Unauthenticated users cannot access batch status.
- [ ] The authorization matrix is enforced for the owner, another user with the same role, other roles, and unauthenticated callers.
- [ ] `GET /api/ingest/{id}` does not fall through to an unscoped query for unsupported/unknown roles.
- [ ] Existing batch ownership is derived server-side and is never accepted from request input.

## Validation

- [ ] Test creation and persistence of an ingestion status record.
- [ ] Test the `queued` state.
- [ ] Test the `processing` state.
- [ ] Test the `done` state.
- [ ] Test the `failed` state.
- [ ] Test valid state transitions.
- [ ] Test invalid/backward state transitions.
- [ ] Test timestamp updates for processing and completion.
- [ ] Test `totalPages`, `processedPages`, and `failedPages`.
- [ ] Test sanitized failure-reason storage and response.
- [ ] Test owner access.
- [ ] Test access denial for a second user with the same role.
- [ ] Test access denial for each other role.
- [ ] Test unauthenticated access.
- [ ] Test unknown/inaccessible batch IDs return `404`.
- [ ] Test repository-level ownership scoping and deny-by-default behaviour.
- [ ] ESLint passes.
- [ ] TypeScript passes.
- [ ] All tests pass.

## Out of Scope

- Batch upload endpoint implementation (AE-042).
- Immutable/WORM storage implementation (AE-043).
- Background worker execution and retry/recovery logic (AE-044).
- `GET /api/ingest` listing endpoint for a user's batches.
