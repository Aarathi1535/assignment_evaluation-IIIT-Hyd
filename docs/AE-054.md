# AE-054 — Cover-Boundary Script Splitting

## Objective

Refactor the existing cover-boundary grouping logic into a dedicated splitting strategy so that additional splitting strategies can be added without mixing page splitting with student identification.

**Architecture update:** This ticket follows the revised architecture established by **#39, #40, #41, and #42**. `AnswerScript` is the script-level identity unit, while splitting determines page membership independently of student identity.

## Scope

- Extract the existing cover-boundary grouping logic from `StudentRosterMappingService`.
- Create a dedicated splitting service/strategy.
- Define a reusable strategy contract such as:
  `split(pages) → ScriptRange[]`
- The strategy receives ordered pages and returns script boundaries only.
- The strategy must have no knowledge of students or roster mapping.
- Update `StudentRosterMappingService` to use the splitting strategy.
- Preserve the existing cover-boundary behavior.

## Acceptance Criteria

- Cover-boundary grouping is implemented by a dedicated splitting strategy.
- The strategy accepts ordered pages and returns `ScriptRange[]`.
- The strategy contains no student or roster logic.
- `StudentRosterMappingService` uses the strategy instead of inline grouping logic.
- Existing cover-boundary behavior remains unchanged.
- When no cover pages are detected, the system does not silently invent a cover boundary; the result is surfaced for manual review.
- Existing tests continue to pass.
- Relevant TypeScript and ESLint checks pass.
