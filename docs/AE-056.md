# AE-056 — Persist Split Result + Link Pages to Scripts

## Objective

Persist the result of script splitting by explicitly linking each `IngestionPage` to its corresponding `AnswerScript`.

**Architecture update:** This ticket follows the revised architecture established by **#39, #40, #41, and #42**. `AnswerScript` is the script-level identity unit, while splitting determines page membership independently of student identity.

## Scope

- Add an optional `answerScript` reference to `IngestionPage`.
- Link every page in a `ScriptRange` to its persisted `AnswerScript`.
- Preserve page ordering and script boundaries.
- Ensure pages from different scripts are not cross-linked.
- Support both cover-page and fixed-page splitting.
- Preserve idempotent reprocessing of the same batch.

## Acceptance Criteria

- Each `IngestionPage` can reference its corresponding `AnswerScript`.
- Pages are linked according to the `ScriptRange` produced by the selected splitting strategy.
- A page cannot contain multiple `AnswerScript` references.
- Page ordering and file boundaries are preserved.
- Reprocessing updates page-to-script links correctly without conflicting relationships.
- Existing cover-page and fixed-page behavior remains unchanged.
- Relevant tests, TypeScript, ESLint, and diff checks pass.

## Out of Scope

- End-to-end batch integration testing — **#46**.
- New splitting strategies.
- Student identification or roster logic.
- Roll-number handling.
- OCR identification.
- Grading logic.

## Dependencies

**Depends on:**

- **#43 / AE-054** — Cover-boundary splitting strategy.
- **#44 / AE-055** — Fixed-page splitting strategy.

**Enables:**

- **#46 / AE-057** — End-to-end batch → scripts integration testing.
