# AE-080 — Ingestion QA Bug Fixes

## Objective
The goal of this ticket is to investigate correctness/reliability issues in the assignment ingestion pipeline based on the E2E and performance evidence collected in AE-078 and AE-079, implement minimal correct fixes in the production code, write regression tests to prevent future regressions, and document the findings.

---

## Reviewed Evidence & Confirmed Bugs
During systematic testing and re-running of ingestion jobs under varying batch configurations, two correctness defects were confirmed:

### 1. Dangling Obsolete AnswerScripts on Re-assembly
*   **Symptom**: When a batch is reprocessed (re-ingested) or the course/exam splitting strategy changes, old `AnswerScript` records remain active (`isActive: true`) in the database.
*   **Root Cause**: In `StudentRosterMappingService.assembleAndMapAnswerScripts`, the service clears the `answerScript` link on `IngestionPage` records in the batch at the start, but never deletes or deactivates the existing `AnswerScript` records for the batch that were not recreated during the current execution. When the split boundaries change (e.g. fewer cover pages are detected or the fixed page count changes), the database is left with orphaned, active `AnswerScript` documents that have no associated pages.
*   **Impact**: Empty and duplicate scripts appear on the Review Dashboard and corrupt the canonical assembly seal calculations.

### 2. Stale Automatic Identifications Block Precedence Signals
*   **Symptom**: Automatic identification scans are skipped on reprocessed scripts that were previously identified by OMR, blocking higher-precedence signals (like a newly decoded QR code) from being applied.
*   **Root Cause**: In `StudentRosterMappingService.assembleAndMapAnswerScripts`, the service checks if a script was previously identified via `existingIdentifiedScript.identificationStatus === IdentificationStatus.IDENTIFIED`. If true, it retains the previous automatic student assignment and source (e.g. OMR), skipping the new QR code extraction result.
*   **Impact**: On retry/re-ingestion, higher precedence automatic identification signals (QR > OMR) are ignored, violating the precedence design rules.

---

## Production Fixes Implemented

Both fixes were implemented in [StudentRosterMappingService.ts](../src/services/StudentRosterMappingService.ts):

### 1. Dangling Obsolete AnswerScripts Cleanup
We added a physical deletion query at the end of the `assembleAndMapAnswerScripts` execution to remove obsolete `AnswerScript` records belonging to the batch:
```typescript
        // Clean up obsolete AnswerScript records that were not recreated during this run
        const processedScriptIds = results.map(s => s._id);
        await AnswerScript.deleteMany({
            batchId,
            _id: { $nin: processedScriptIds }
        });
```

### 2. Overwrite Protection Limited to Operator Overrides
We modified the check in the assembly loop to preserve previous student mappings **only** if they were manually set by an operator (`identificationSource === IdentificationSource.OPERATOR`). Previous automatic assignments (`QR`, `OMR`, `OCR`, or `null`) are now safely recalculated and updated:
```typescript
            if (existingIdentifiedScript && existingIdentifiedScript.identificationSource === IdentificationSource.OPERATOR) {
                resolvedStudentId = existingIdentifiedScript.student as mongoose.Types.ObjectId | null;
                identificationStatus = existingIdentifiedScript.identificationStatus as IdentificationStatus;
                identificationSource = existingIdentifiedScript.identificationSource as any;
                needsManualId = existingIdentifiedScript.needsManualId || false;
                manualIdReason = (existingIdentifiedScript.manualIdReason as ManualIdReason | null) || null;
                if (existingIdentifiedScript.identificationSource === IdentificationSource.OPERATOR) {
                    candidateStudentId = existingIdentifiedScript.candidateStudentId || null;
                }
            }
```

## Regression Test Coverage
We created a dedicated regression test file [AE080BugFix.test.ts](../src/__tests__/AE080BugFix.test.ts) covering:
1.  **Dangling Script Cleanup**: Verifies that when a batch's cover page configuration changes, obsolete scripts are deleted and only active/valid scripts remain.
2.  **Precedence Overwrite**: Verifies that re-running mapping with a newly resolved QR code overwrites a previous OMR assignment.
3.  **Operator Override Preservation**: Verifies that re-running mapping does not overwrite manual student overrides assigned by a reviewer.
