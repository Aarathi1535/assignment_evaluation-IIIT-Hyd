# AE-049 — Tests for Page Extraction + Storage

## Objective

Add fixture-based integration coverage for the PDF/image ingestion pipeline, verifying that real input files pass through the full ingestion flow and produce the expected page counts, stored assets, Page documents, ordering, and failure/idempotency behaviour.

## Scope

- Add small, static PDF and image fixtures under `src/__tests__/fixtures/`.
- Run real fixture bytes through the full ingestion pipeline.
- Verify expected page counts.
- Verify normalized page assets are stored.
- Verify corresponding Page documents are created correctly.
- Verify deterministic `(fileIndex, pageNumber)` ordering.
- Verify source batch/file associations.
- Verify relevant failure and idempotency paths.
- Add dedicated coverage for PDF page-count reconciliation between the upload-time guard and the authoritative renderer count.
- Verify fixture files are tracked by Git and are not silently excluded by ignore rules.
- Verify test runs do not leave stray runtime artifacts under `data/`.

## Test Boundary

AE-049 owns the **fixture-based integration suite**.

The individual feature tickets own focused unit tests for their own logic:

- **AE-046** — unit tests for PDF page rendering and rendering-related logic using small/in-memory inputs.
- **AE-047** — unit tests for thumbnail generation and normalization.
- **AE-048** — unit tests for image normalization and mixed-input handling.
- **AE-049** — real static PDF/image fixtures through the full ingestion pipeline.

This separation prevents duplicate coverage while ensuring the complete pipeline is tested with real file bytes.

## Acceptance Criteria

- Static PDF and image fixtures are committed under `src/__tests__/fixtures/`.
- Fixtures are genuinely small and suitable for repeated CI execution.
- PDF page counts in tests are known-correct literals rather than values generated by the production parser.
- A real single-page PDF passes through the full pipeline and produces the expected Page document and stored asset.
- A real multi-page PDF passes through the full pipeline and produces the expected number of Page documents and stored assets.
- Image fixtures pass through the full pipeline and produce the expected single-page representation.
- Mixed PDF/image inputs produce the correct pages and associations.
- `(fileIndex, pageNumber)` ordering is verified through the full pipeline.
- Retries/idempotent processing do not create duplicate Page documents or derived assets.
- Invalid multi-file input follows the AE-048 reject-whole-batch behaviour.
- The page-count reconciliation fixture proves that the authoritative renderer count is used.
- The reconciliation fixture reaches `done` with `processedPages === totalPages`.
- Fixtures are tracked by Git and are not silently swallowed by ignore rules.
- Test execution does not result in stray tracked files under `data/`.
- ESLint, TypeScript, the complete test suite, and CI pass.
