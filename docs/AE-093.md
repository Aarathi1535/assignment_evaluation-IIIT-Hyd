# AE-093: No-PII-Leak Tests

This document details the objective, design, and verification results of the strict privacy and PII leak tests implemented for the server-side anonymization serializer.

## Privacy Guarantee
We guarantee that TA viewers in blind-grading mode will never be exposed to a student's real identity. Specifically:
- **Zero Student User Leakage**: Real student name, email, photo/profile fields, and MongoDB ObjectIds are entirely stripped.
- **Zero Raw Script ID Leakage in References**: Raw AnswerScript Mongo ObjectIds are never used as script references.
- **Zero Diagnostic Leakage**: File paths, filenames, batch IDs, scanner match history, and manual matching diagnostics are excluded.

## Strategy: Targeting Serializers Directly
Instead of testing mock TA routes (which do not exist yet in the codebase), the tests target the centralized server-side serializer [`src/lib/anonymizer.ts`](file:///c:/Users/AARATHISREE/Desktop/IIIT%20Hyd%20-%20Assignment%20Evaluation/Project%20Repo/assignment-evaluator/src/lib/anonymizer.ts) directly. Testing the serializer ensures that all future TA endpoints implementing this serializer inherit these identical, robust privacy validations.

## Exact Allowlist Strategy
Rather than asserting only the absence of known PII fields (which can lead to leaks if new properties are added to model schemas in the future), the tests assert an **exact allowlist** match on the keys returned in the JSON payload:
- **Permitted AnswerScript fields**:
  - `_id`, `exam`, `anonymousId`, `scriptReference`, `startPageNumber`, `endPageNumber`, `pageCount`, `isActive`, `createdAt`, `updatedAt`
- **Permitted Grade fields**:
  - `_id`, `answerScript`, `rubric`, `marksAwarded`, `totalScore`, `feedback`, `isFinal`, `question`, `createdAt`, `updatedAt`

Any key present on the serialized object that is not in the explicit allowlist will cause the test suite to fail immediately.

## Nested/Populated PII Protection
The tests mock a fully-populated Mongoose document using `.populate('student')` prior to serialization. The serializer strips all populated details CPU-side and ensures that the output object contains exactly and only the allowlisted keys, preventing accidental leaks of populated nested data. The same exact allowlist verification is applied recursively to nested `answerScript` objects inside serialized `Grade` documents.

## Script Reference & Fallback Coverage
- **Identified student**: Asserts formatting follows `Script #${anonymousId}`.
- **Unassigned fallback**: Asserts unassigned scripts (where `student = null`) receive `Script #UNASSIGNED-XXXXXX`, where the 6-character suffix is deterministic, stable, and completely hides the raw ObjectId.
- **Configuration Integrity (Fail-Fast)**: Asserts that deleting `ORIGINAL_STORAGE_HMAC_SECRET` from environment variables correctly triggers a configuration error instead of silently falling back to a hardcoded or predictable salt.
