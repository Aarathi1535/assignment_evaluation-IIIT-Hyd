# [AE-068] Store per-page enhancement parameters

## Objective

Allow enhancement parameters to be stored per page as non-destructive overrides that regenerate the page's derived enhanced image without modifying the immutable original.

## Acceptance criteria

- [ ] Each page can store its current enhancement parameters.
- [ ] Parameters are applied to the immutable original to regenerate the derived enhanced image.
- [ ] The derived enhanced image is the image used by the viewer and downstream page-processing consumers.
- [ ] Updating parameters replaces the previous derived enhanced asset deterministically.
- [ ] The original uploaded image is never modified or replaced.
- [ ] Enhancement parameter changes are audit-logged.
- [ ] Only authorized users can modify enhancement parameters.
- [ ] Stored parameters can reproduce the same derived image deterministically.

## Validation

- [ ] Test storing and retrieving enhancement parameters for individual pages.
- [ ] Change parameters and verify the derived enhanced image is regenerated.
- [ ] Verify the viewer retrieves the current derived enhanced image.
- [ ] Verify the original source remains byte-identical after repeated changes.
- [ ] Verify parameter changes create audit records.
- [ ] Verify unauthorized parameter changes are rejected.
- [ ] Verify the same source and parameters reproduce the same result.
- [ ] Run `npx vitest run`.
- [ ] Run `npx tsc --noEmit`.
- [ ] Run `npm run lint`.
- [ ] Run `git diff --check`.

## Out of scope

- Replacing or deleting the immutable original image.
- Implementing the deskew algorithm.
- Implementing the brightness/contrast algorithm.
- Student identification or manual tagging.
