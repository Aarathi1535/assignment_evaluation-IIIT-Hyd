# AE-062 — Manual Student-ID Assignment UI

## Objective

Provide an operator-facing UI to recover answer scripts that could not be
automatically identified during ingestion.

## Scope

- Display scripts that require manual identification.
- Show the script's page thumbnails/context.
- Display the roster of students belonging to the selected exam.
- Allow an authorized reviewer to select a student.
- Save the selected student mapping using the existing identification backend.
- Show the updated identification state after a successful save.

## Authorization

- The UI is an operator tool.
- Require `EDIT_EXAM` permission.
- Restrict access to users who can access the corresponding exam/batch.
- Graders and students must not be able to perform manual identification.
- Reuse the existing owner-scoped authorization and identification API.

## Acceptance Criteria

- Unidentified scripts are clearly marked as requiring manual review.
- Reviewer can open an unidentified script.
- Script pages/context are visible before assigning a student.
- Only students from the corresponding exam roster are selectable.
- Reviewer can select a student and save the mapping.
- Successful mapping updates the displayed student identity.
- Mapping persists after page refresh.
- Existing backend validation and uniqueness rules are respected.
- Authorization failures are handled clearly.
- Errors during saving are displayed without losing the current review context.
- Existing identification/audit behavior is reused rather than duplicated.
- Relevant tests, TypeScript, ESLint, and diff checks pass.

## Out of Scope

- New student-identification algorithms.
- OCR/QR changes.
- Changes to roster membership.
- New identification backend endpoints.
- Script/page remap, merge, split, or reorder operations — **AE-063 / AE-064**.
- Duplicate/blank page detection — **AE-065**.
- Reimplementation of ingestion or script splitting logic.

## Dependencies

**Depends on:**

- Existing AnswerScript/page persistence.
- Existing student roster/exam data.
- Existing answer-script identification endpoint.
- **AE-064** — backend correction foundation.

**Enables:**

- Manual recovery of scripts that could not be automatically identified.
