# AE-087: Professor Allocation UI with Safe Preview

## Overview

Implemented a read-only allocation preview functionality alongside a comprehensive configuration UI that lets professors preview allocation rules (EQUAL, QUESTION, seeded RANDOM) before committing them to the database.

## Implemented Changes

### 1. Pure Calculation Logic Refactor
- Refactored `AllocationService.ts` to separate the pure mathematical distribution calculations (`computeDistribution`) from database state transitions/transactions.
- Extracted `getEligibleAndExcludedScripts` to partition answer scripts into eligible and excluded sets. It provides descriptive reasons for exclusions (e.g. `Inactive script`, `Student not identified`, or `manualIdReason` such as `NO_CODE_FOUND`).
- The real allocation endpoints and the new preview endpoint share the same calculation logic, ensuring preview results match committed results exactly.

### 2. Read-Only Preview API
- Implemented a new safe read-only preview endpoint: `POST /api/exams/[id]/allocate/preview`.
- Gated the endpoint with `Permission.ALLOCATE_SCRIPTS` permission and the exam ingestion approval check (`IngestionApprovalService.requireApproved`).
- Returns counts per TA, count of eligible scripts, total excluded scripts count, and exclusion counts grouped by reason.

### 3. Allocation Settings & TA retrieval API
- Added a `GET` handler to `POST /api/exams/[id]/allocate/route.ts`.
- It fetches and returns the exam details (title, ingestion status, number of questions) and the course's teaching assistants populated with their names and emails.

### 4. Interactive Professor Allocation UI
- Added an "Allocate" button to the professor exams dashboard listing.
- Built `AllocationView.tsx` with:
  - Select TAs checklists (using a grid of cards showing names/emails).
  - Allocation Rule selection (Equal, By Question, or Seeded Random).
  - Deterministic random seed input box and generator.
  - Integration block warning professors if ingestion approval is pending.
  - Interactive "Preview Allocation" displaying counts per TA, eligible script totals, and script exclusions.
  - "Confirm Allocation" button calling the real allocate API and redirecting on success.

## Safety & Security

- **Safe Preview**: The preview endpoint contains no database write operations (neither creates, updates, nor deletes `Allocation` documents), keeping it side-effect-free.
- **Blind Grading Compliance**: The API response and UI only return and display aggregated counts of exclusions grouped by reason. Individual script IDs, student names, and emails are never exposed in the preview dataset, ensuring complete compatibility with blind grading.
- **Gate Enforcement**: Enforces that ingestion must be approved before preview or allocation can proceed.

## Verification

- Added comprehensive tests in `src/__tests__/AllocationPreview.test.ts` covering:
  - Settings retrieval GET endpoint.
  - Equal allocation calculations and TA counts.
  - Question-based allocation mapping.
  - Seeded random deterministic behavior.
  - Exclusion identification (inactive, unidentified, manual-review scripts) and lack of student name exposure.
  - Ingestion approval check.
  - Ensuring no allocations are written to the database on preview.
