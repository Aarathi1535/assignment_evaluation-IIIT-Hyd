# AE-051 — Map Decoded ID → Roster Student

## Objective

Assemble `AnswerScript` records from grouped `IngestionPage` documents based on cover-sheet boundaries, resolve candidate student identifiers against the associated exam's enrolled roster, and persist idempotent, traceable `AnswerScript` records.

## Scope

- Consume AE-050's persisted candidate identifier fields (`isCoverPage`, `candidateStudentId`, `decodeOutcome`).
- Group pages into scripts using the cover-sheet boundary rule in `(fileIndex, pageNumber)` order.
- Resolve `candidateStudentId` strictly against the current exam roster (`Exam.enrolledStudents`, `StudentMapping`, course enrollment).
- Create/assemble `AnswerScript` records for every valid detected script group.
- Enforce deterministic source identity and idempotency based on `(batchId, fileIndex, startPageNumber)`.
- Make `AnswerScript.student` nullable so unidentified scripts (unreadable barcodes, missing students, or duplicate conflicts) can persist.
- Preserve the existing `(exam, student)` unique constraint for identified scripts via a partial filter index.
- Surface duplicate student conflicts without overwriting or index violation.
- Enforce owner scoping using the existing `buildBatchQuery` deny-by-default 404-not-403 pattern.

## Grouping & Assembly Flow

```
IngestionPages (sorted by fileIndex ASC, pageNumber ASC)
                    │
                    ▼
          Cover-Sheet Boundary Grouping
          - isCoverPage === true starts new script
          - Subsequent pages up to next cover belong to script
                    │
                    ▼
          AnswerScript Group
          { batchId, fileIndex, startPageNumber, endPageNumber, pageCount }
                    │
                    ▼
          Roster Resolution
          candidateStudentId ──▶ Exam Roster ──▶ Matching User ──▶ User._id
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
    Enrolled Student     Not Enrolled / Unknown / Duplicate
    student: User._id    student: null
          │                   │
          └─────────┬─────────┘
                    │
                    ▼
    Upsert AnswerScript (batchId, fileIndex, startPageNumber)
```

## Acceptance Criteria

- [x] Consumes `isCoverPage`, `candidateStudentId`, `decodeOutcome` without rescanning images.
- [x] Assembles contiguous page ranges into scripts based on cover-sheet boundaries in `(fileIndex, pageNumber)` order.
- [x] Resolves candidate identifier strictly against the exam's enrolled roster.
- [x] Stores `User._id` in `AnswerScript.student` upon successful identification.
- [x] Unidentified or unenrolled scripts persist with `student: null`.
- [x] Unique index enforces `(batchId, fileIndex, startPageNumber)` source identity.
- [x] Partial index enforces `(exam, student)` uniqueness only when `student` is present.
- [x] Duplicate student conflict preserves new script with `student: null` without overwriting the existing script.
- [x] Scoped to authenticated owner context with deny-by-default 404 behavior.
- [x] Unit and integration tests verify all scenarios.
