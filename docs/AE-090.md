# AE-090: Centralized Anonymization Serializer

This document details the objective, architecture, implementation, and verification of the server-side anonymization serializer.

## Ticket Objective
The goal is to build a reusable server-side serializer/projection mechanism to support future TA-facing endpoints. When an exam's blind-grading mode is enabled, the serializer must strip student PII and only expose a strict allowlist of safe fields to TAs, while retaining full data access for professors and administrators.

## Architecture & Design Decisions
- **Centralized Service**: Implemented in [`src/lib/anonymizer.ts`](file:///c:/Users/AARATHISREE/Desktop/IIIT%20Hyd%20-%20Assignment%20Evaluation/Project%20Repo/assignment-evaluator/src/lib/anonymizer.ts) to enable clean reuse by future Day 4 TA work-queue and grading endpoints.
- **Server-side Determination**: The anonymization logic evaluates context (the authenticated viewer role and the exam settings) purely server-side. It does not respect client-supplied flags, preventing tampering or unauthorized exposure of student identities.
- **Explicit Allowlist**: We use an explicit allowlist of safe fields for blind-mode output rather than a denylist, ensuring new fields added to models in the future are secure by default.
- **Composite Key Lookup**: Maps anonymous IDs using the composite key format `${examId}:${studentId}`. Since students can be enrolled in multiple courses/exams, mapping purely by `studentId` can cause ID clashes across different exams. Using the composite key guarantees that correct exam-specific anonymous IDs are mapped during bulk serialization.
- **PII Replaced with anonymousId**: Exposes `anonymousId` from `StudentMapping` in place of student names or student user IDs. No new anonymous ID system is created (satisfying AE-092 reuse requirements).

## Server-Side Enforcement Mechanism
The serializer evaluates anonymization based on:
1. **Exam Configuration**: `blindGrading: true` configured on the `Exam` model.
2. **Viewer Role**: Checked against the viewer role. If the viewer is `PROFESSOR` or `ADMIN`, anonymization is bypassed. If the viewer is `TA` (or any other role), and blind grading is enabled, anonymization is enforced.

## Allowed Blind-Mode Response Shape
The blind-mode response shape is strictly minimized to prevent leakage of diagnostic details or file paths.

## PII Fields Protected
The following identifying details are stripped and omitted in blind-mode:
- Student user objects and references (`student`).
- Candidate student ID strings (`candidateStudentId`, which contains the format `examId:studentId`).
- Scanned QR student IDs (`qrStudentId`).
- Scanned OMR student IDs (`omrStudentId`).
- Metadata fields containing scanned data strings (`metadata`).
- File diagnostics and internal storage paths (`filePath`, `filename`, `batchId`, `fileIndex`).
- Scoring and matching exceptions (`needsManualId`, `manualIdReason`, `decodeOutcome`).

## Prevention of Nested/Populated PII
Because the blind-mode serialization maps fields explicitly from an allowlist (constructing a new plain JavaScript object), any populated student details or custom fields dynamically added to the MongoDB documents are discarded. Nested `answerScript` objects within `Grade` objects are recursively serialized using the same safe allowlist.

## Bulk Query N+1 Mitigation
To prevent N+1 database queries when serializing list responses (such as a TA work-queue array), `Anonymizer.serializeAnswerScripts` and `Anonymizer.serializeGrades` bulk-fetch the required mappings. They extract all relevant `examId` values from the input array, issue a single bulk query to the `StudentMapping` collection, and load the mappings into a memory lookup map with composite keys:
```typescript
const mappings = await StudentMapping.find({ exam: { $in: examIds } }).lean();
for (const m of mappings) {
    if (m.student && m.exam) {
        const key = `${m.exam.toString()}:${m.student.toString()}`;
        anonymousIdMap[key] = m.anonymousId;
    }
}
```
This reduces database roundtrips from $O(N)$ down to a single query $O(1)$.

## Professor / Admin Behavior
Professors and Admins bypass anonymization checks. Their serialized responses return full documents, including `student` user details, un-anonymized metadata, and scanner diagnostics.

## Future Day 4 TA Route Integration
The `Anonymizer` class exports static methods:
- `Anonymizer.serializeAnswerScript(script, viewer)`
- `Anonymizer.serializeAnswerScripts(scripts, viewer)`
- `Anonymizer.serializeGrade(grade, viewer)`
- `Anonymizer.serializeGrades(grades, viewer)`

Future Day 4 endpoints (e.g. `GET /api/ta/work-queue` or `GET /api/ta/grades`) can simply import `Anonymizer` and wrap their database results before sending them to the client:
```typescript
const plainScripts = await AnswerScript.find({ exam: examId }).lean();
const serialized = await Anonymizer.serializeAnswerScripts(plainScripts, viewerContext);
return NextResponse.json({ success: true, data: serialized });
```
