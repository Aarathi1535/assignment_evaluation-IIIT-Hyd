# AE-104b — Absolute TA Grading Pace / Deadline-Based Bottleneck Detection

## Objective

Provide real-time absolute grading pace tracking and deadline-based bottleneck detection for an exam. This feature introduces an explicit, optional `gradingDeadline` to the `Exam` model, calculates elapsed vs. total grading duration from the authoritative allocation start time, and flags teaching assistants who are materially lagging behind schedule (by more than 20 percentage points).

---

## 1. Data Model & Field Ownership

### 1.1 `gradingDeadline` Field
* **Model**: `Exam` (`src/models/Exam.ts`)
* **Type**: `Date | null` (optional, default `null`).
* **Backward Compatibility**: Existing exam records without a `gradingDeadline` default to `null`. No artificial or heuristic deadlines are fabricated.

### 1.2 Ownership & Permissions
* **Creation**: Course Professors and Administrators with `Permission.CREATE_EXAM` via `POST /api/exams`.
* **Update**: Exam owners (Professors) and Administrators with `Permission.EDIT_EXAM` via `PUT /api/exams/[id]`.
* **Chronological Constraint**: `gradingDeadline` must be on or after `examDate` (`gradingDeadline >= examDate`). Setting a deadline prior to the exam date returns `400 Bad Request`.

### 1.3 Freeze Rule (Grading Commenced Guard)
* In accordance with the **AE-091 freeze precedent**, once grading has commenced for an exam, the grading deadline becomes immutable.
* **Grading Commenced Definition**:
  1. Any `Allocation` document for the exam has a status other than `PENDING` (`IN_PROGRESS` or `COMPLETED`), OR
  2. Any `Grade` document exists for the exam's answer scripts.
* **Rejection Response**: Updating `gradingDeadline` on a commenced exam throws `400 Bad Request` with message:
  `"Cannot update grading deadline: grading has already commenced for this exam"`.

## 2. Authoritative Grading Start & Mathematical Pace Calculation

### 2.1 Grading Start Definition
* **Grading Start ($T_{\text{start}}$)** is defined as the earliest allocation creation timestamp:
  $$T_{\text{start}} = \min(\text{Allocation.createdAt})$$
* This establishes the exact moment scripts were partitioned and distributed to TAs for grading. Unrelated timestamps (`examDate`, `approvedAt`, `assemblySealAt`) are not used.

### 2.2 Mathematical Formulas

Let $T_{\text{start}} = \text{gradingStart}$, $T_{\text{deadline}} = \text{gradingDeadline}$, and $T_{\text{now}} = \text{Date.now()}$.

1. **Total Duration**:
   $$\text{totalDuration} = T_{\text{deadline}} - T_{\text{start}}$$
2. **Elapsed Duration**:
   $$\text{elapsedDuration} = \max(0, T_{\text{now}} - T_{\text{start}})$$
3. **Expected Completion Ratio ($\text{expectedCompletionRatio}$)**:
   $$\text{expectedCompletionRatio} = \begin{cases} 0.0 & \text{if } T_{\text{now}} < T_{\text{start}} \\ \min\left(1.0, \dfrac{T_{\text{now}} - T_{\text{start}}}{T_{\text{deadline}} - T_{\text{start}}}\right) & \text{if } T_{\text{start}} \le T_{\text{now}} \le T_{\text{deadline}} \\ 1.0 & \text{if } T_{\text{now}} > T_{\text{deadline}} \end{cases}$$
4. **Actual Completion Ratio ($\text{completionRatio}$)**:
   $$\text{completionRatio} = \frac{\text{graded}}{\text{total}} \quad (\text{for eligible TAs with } \text{total} > 0)$$
5. **Pace Lag**:
   $$\text{paceLag} = \max(0, \text{expectedCompletionRatio} - \text{completionRatio})$$
6. **Bottleneck Threshold**:
   A TA is flagged as an absolute pace bottleneck if and only if their progress is materially lagging behind expected pace by **more than 20 percentage points (0.20)**:
   $$\text{isBottleneck} = (\text{expectedCompletionRatio} - \text{completionRatio}) > 0.20$$

#### Boundary Examples:
| Expected Ratio | TA Ratio | Difference | Bottleneck Status | Explanation |
| :--- | :--- | :--- | :--- | :--- |
| **80% (0.80)** | **55% (0.55)** | **25% (0.25)** | **`true`** | Lag (25%) exceeds the 20% threshold ($0.25 > 0.20$). |
| **80% (0.80)** | **60% (0.60)** | **20% (0.20)** | **`false`** | Exactly on the 20% boundary ($0.20 \ngtr 0.20$). |
| **80% (0.80)** | **65% (0.65)** | **15% (0.15)** | **`false`** | Lag is within the acceptable 20% margin. |
| **100% (1.00)** *(Deadline Passed)* | **75% (0.75)** | **25% (0.25)** | **`true`** | Incomplete grading after deadline exceeds 20% lag. |
| **100% (1.00)** *(Deadline Passed)* | **100% (1.00)** | **0% (0.00)** | **`false`** | Grading completed on/after deadline. |

## 3. Edge Cases & Missing Deadline Fallback

| Scenario | `paceAvailable` | `paceReason` | Behavior |
| :--- | :--- | :--- | :--- |
| **No Deadline Set** | `false` | `GRADING_DEADLINE_NOT_SET` | Returns TA progress without fabricated pace. |
| **No Allocations Generated** | `false` | `NO_ALLOCATIONS` | Returns empty progress and 0 bottleneck count. |
| **Invalid Window ($T_{\text{deadline}} \le T_{\text{start}}$)** | `false` | `INVALID_DEADLINE_WINDOW` | Avoids division by zero or negative durations. |
| **TA with Total = 0** | `true` (if exam pace valid) | `null` | Excluded from pace evaluation (`isBottleneck: false`). |

## 5. Relationship to AE-104a & Privacy Guarantees

* **AE-104a (Relative Cohort Comparison)**: Evaluates TA completion ratios relative to the cohort median for the exam.
* **AE-104b (Absolute Deadline Pace)**: Evaluates TA completion ratios relative to the time elapsed towards an explicit `gradingDeadline`.
* **Zero Student PII**: No student names, emails, roll numbers, or answer script file paths are exposed in the progress or pace metrics.
