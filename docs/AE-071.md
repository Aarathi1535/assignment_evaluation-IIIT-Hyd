# AE-071: OMR Template Configuration per Exam

## Purpose
AE-071 establishes the model, validation schemas, and configuration APIs for managing OMR templates per Exam. The template defines the locations of student ID bubbles using a normalized coordinate system relative to the canonical enhanced cover page.

## Data Ownership
OMR template configuration is owned and managed strictly at the **Exam level** (`Exam.omrTemplate`).
- It is **never** stored on individual page or AnswerScript records.
- AnswerScript records continue to own the authoritative student identity according to AE-072.
- During page processing, OMR readers fetch and apply the associated exam's template to extract student IDs.

## The Canonical Enhanced/Deskewed Page Image Requirement
OMR templates are defined against the canonical enhanced, deskewed page image, not the immutable original upload.
- **Do not** measure bubble coordinate systems against the raw/original scan.
- The pipeline processes the page through deskewing (AE-066) and contrast enhancement (AE-067) before the OMR reader (AE-070) applies coordinates from the template.
- Overwriting original page assets (`originalStorageKey`, etc.) is strictly prohibited.

## Normalized 0.0 - 1.0 Coordinate System
To guarantee page size and resolution/DPI independence (e.g. template works identically on 2480x3508 and 1240x1754 page dimensions):
- All spatial coordinates (`x`, `y`) and dimensions (`width`, `height`) must be normalized floats in the range `[0.0, 1.0]`.
- Coordinates must be defined as ratios of page width and page height.
  - `x = 0.25` is 25% of page width from the left margin.
  - `y = 0.40` is 40% of page height from the top margin.
- Coordinates specify the top-left corner of the bubble bounding region.
- Pixel boundaries are derived at runtime:
  - `pixelX = x * pagePixelWidth`
  - `pixelY = y * pagePixelHeight`
  - `pixelWidth = width * pagePixelWidth`
  - `pixelHeight = height * pagePixelHeight`

## Bubble-Grid Schema Structure
The template contains the following structure:
- `pageIndex`: Index of the target sheet within the script (e.g., `0` for the cover sheet).
- `columns`: Array of OMR column configs, each containing:
  - `columnIndex`: Contiguous 0-indexed integer (from left to right) representing the position of the digit/character in the student ID.
  - `bubbles`: Array of bubble configurations for that column, each containing:
    - `value`: Digit or character represented by the bubble (e.g. `'0'` - `'9'`).
    - `x`: Top-left normalized X coordinate.
    - `y`: Top-left normalized Y coordinate.
    - `width`: Normalized width of the bubble region.
    - `height`: Normalized height of the bubble region.

## Strict Validation Rules
Any creation or update request for an OMR template undergoes strict validation. An invalid configuration must fail immediately, and a missing/invalid template configuration produces a safe configuration/fallback state rather than guessing a student ID.
The schema rejects:
- Missing required fields.
- Malformed coordinates (not numbers).
- Coordinates or dimensions outside the range `[0.0, 1.0]`.
- Region overflows (e.g., `x + width > 1.0` or `y + height > 1.0`).
- Negative widths/heights.
- Empty bubble grids (zero columns or zero bubbles in a column).
- Duplicate column indices (`columnIndex`).
- Non-contiguous column indices (indices must start at 0 and increase sequentially: 0, 1, 2, ...).
- Duplicate bubble values in the same column (e.g. two bubbles representing `'1'`).
- Duplicate/conflicting bubble positions across the entire template (two bubbles with the exact same coordinate).

## Relationship to Future Components
- **AE-070 (OMR Reader)**: Fetches `exam.omrTemplate` during batch page analysis, scales coordinates to the enhanced image dimensions, and measures bubble fill ratios to determine student ID digit values.
- **AE-072 (Identification Precedence)**: Defines the precedence order: Manual/Operator override > QR > OMR. The OMR configuration created in AE-071 establishes the definition that AE-070 consumes, keeping the precedence rules untouched.
