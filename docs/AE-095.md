# AE-095 — TA Work-Queue UI

## Objective
Implement the TA-facing grading work-queue dashboard supporting paginated results and navigation. It allows authenticated TAs to see their active script grading allocations, verify status, navigate across pages, and open specific scripts or questions in the grading portal via secure paths.

## Implementation
*   **Queue Page**: Modified `src/app/(dashboard)/ta/page.tsx` to display the work-queue dashboard with pagination controls.
*   **API Used**: Calls `GET /api/allocations?page={page}&limit=20` client-side, dynamically updating the query parameters as the user transitions pages.
*   **Pagination Navigation Footer**: Added Previous and Next buttons with IDs `prev-page-btn` and `next-page-btn` at the bottom of the table.
    *   Previous button is disabled if `hasPreviousPage` is false or during page loading.
    *   Next button is disabled if `hasNextPage` is false or during page loading.
    *   Clicking a button fetches the respective page from the allocations API.
*   **Displayed Fields**: Displays safe non-PII values: Answer Script Reference / Anonymous ID, Exam context/ID, Context Mode (e.g. "Question X" or "Whole Script"), status badge (`PENDING`, `IN_PROGRESS`, `COMPLETED`), and an "Open Grader" action button.
*   **Stats Dashboard**: Dynamically computes stats card values (Assigned Exams count, Pending Grading count, Completed Grading count) from the loaded page's allocations.
*   **Loading/Empty/Error States**:
    *   *Loading*: Displays the standard animated loading spinner with "Loading queue..." description.
    *   *Empty*: Renders the `EmptyState` component with check square icon when the TA has zero allocations returned from a successful request.
    *   *Error*: Renders a red warning alert banner detailing the exact API or network error, and replaces the allocations list/empty state inside the card with a clean error descriptor.
*   **Question-wise Navigation**: Action button links directly to:
    *   Question-wise allocations: `/grading/[scriptId]/question/[questionNumber]`
    *   Whole-script allocations: `/grading/[scriptId]`

## Privacy
*   **Anonymization Representation**: Renders `scriptReference` or `anonymousId` (e.g. `Script #ANON-POTTER-777`) for blind-graded exams.
*   **No Identity Rendering**: Student name fields, student roll numbers, or raw student IDs are never read, derived, or rendered on the page. The frontend does not construct client-side anonymization logic; it consumes the secure representation supplied directly by the paginated backend.
