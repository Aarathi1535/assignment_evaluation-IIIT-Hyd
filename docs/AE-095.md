# AE-095 — TA Work-Queue UI

## Objective
Implement the TA-facing grading work-queue dashboard. It allows authenticated TAs to see their active script grading allocations, verify status, and open specific scripts or questions in the grading portal via secure paths.

## Implementation
*   **Queue Page**: Modified `src/app/(dashboard)/ta/page.tsx` to display the work-queue dashboard.
*   **API Used**: Calls `GET /api/allocations` client-side upon page load.
*   **Displayed Fields**: Displays safe non-PII values: Answer Script Reference / Anonymous ID, Exam context/ID, Context Mode (e.g. "Question X" or "Whole Script"), status badge (`PENDING`, `IN_PROGRESS`, `COMPLETED`), and an "Open Grader" action button.
*   **Stats Dashboard**: Dynamically computes stats card values (Assigned Exams count, Pending Grading count, Completed Grading count) from the loaded allocations array.
*   **Loading/Empty/Error States**:
    *   *Loading*: Displays the standard animated loading spinner with "Loading queue..." description.
    *   *Empty*: Renders the `EmptyState` component with check square icon when the TA has zero allocations.
    *   *Error*: Renders a red warning alert banner detailing the exact API or network error.
*   **Question-wise Navigation**: Action button links directly to:
    *   Question-wise allocations: `/grading/[scriptId]/question/[questionNumber]`
    *   Whole-script allocations: `/grading/[scriptId]`
    These targets route to minimal placeholder components established in the routing structure.

## Privacy
*   **Anonymization Representation**: Renders `scriptReference` or `anonymousId` (e.g. `Script #ANON-POTTER-777`) for blind-graded exams.
*   **No Identity Rendering**: Student name fields, student roll numbers, or raw student IDs are never read, derived, or rendered on the page. The frontend does not construct client-side anonymization logic; it consumes the secure representation supplied directly by the AE-094 backend.
